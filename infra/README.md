# Performance — Infra

AWS CDK (TypeScript) stack for the Performance app's backend.

## Stacks

- **`PerformanceTelemetry`** — session-log ingest **and** chat proxy.
  - S3 bucket for log storage (1-year lifecycle, RETAIN on stack destroy).
  - DynamoDB `performance-installations` table for per-install metadata + chat token budgets.
  - **Ingest Lambda + function URL** — validates `Authorization: Bearer <token>`, writes to S3 + DDB.
  - **Chat proxy Lambda + function URL** — validates bearer + install ID, enforces per-install monthly token caps (`MONTHLY_INPUT_CAP` / `MONTHLY_OUTPUT_CAP` env vars), forwards to Anthropic with response streaming. See `docs/LAMBDA_CHAT_PROXY.md`.
  - Secrets Manager `performance/telemetry/bearer-token` — shared token baked into app builds; auto-generated by Secrets Manager on first deploy and stable across redeploys.
  - SSM `/performance/chat/anthropic-api-key` — Anthropic API key, **created out-of-band** (see below).
  - Monthly $50 cost budget with email alarm at 80%. `PerformancePlugins` is tagged `Project=Performance` so its costs roll up here.
- **`PerformancePlugins`** — bundled-plugin hosting.
  - S3 bucket `performance-plugins-<acct>` with a public-read bucket policy (ACL / listing still blocked). Objects are the archives produced by `scripts/bundled-plugins/package-all.sh` + a top-level `manifest.json` written by `publish.sh`.
  - No CloudFront — direct S3 HTTPS URLs are fine for the tester population; the policy leaves room to slide an OAC-fronted distribution in front without changing the URL scheme.
  - `RemovalPolicy.RETAIN`. See `docs/BUNDLED_PLUGINS.md` for the download / install flow.

## One-time setup

```bash
cd infra
npm install
# bootstrap CDK in your account/region (once per account + region)
npx cdk bootstrap aws://<account-id>/us-east-1

# Create the Anthropic API key SSM parameter (only once; CDK references but
# does not manage the value, so the secret never appears in templates).
aws ssm put-parameter \
    --name /performance/chat/anthropic-api-key \
    --type SecureString \
    --value sk-ant-... \
    --no-overwrite
```

## Deploy / diff / destroy

```bash
npx cdk diff      # preview changes
npx cdk deploy    # apply
npx cdk destroy   # remove stack (bucket + DDB retained by design)
```

After a deploy, capture outputs:
- **IngestUrl** — baked into the Performance app.
- **ChatProxyUrl** — baked into the Performance app.
- **BearerTokenSecretName** — read the actual token via:
  ```bash
  aws secretsmanager get-secret-value \
      --secret-id performance/telemetry/bearer-token \
      --query 'SecretString' --output text
  ```

Or just run `scripts/fetch-telemetry-config.sh` from the repo root to grab everything at once into `keys/telemetry.json`.

## Rotating the bearer token

```bash
aws secretsmanager delete-secret \
    --secret-id performance/telemetry/bearer-token \
    --force-delete-without-recovery
npx cdk deploy   # auto-generates a fresh value
# then re-run fetch-telemetry-config.sh and rebuild the app
```

## Why retained resources

`RemovalPolicy.RETAIN` on the bucket and DDB table means `cdk destroy`
tears down the Lambda + URL + budget but leaves data intact. Reason:
data loss from an accidental `destroy` is worse than the cost of a few
orphaned resources you can delete manually if truly unneeded.
